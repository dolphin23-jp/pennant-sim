# Pennant Sim 開発ロードマップ

この文書は、今後の編集者・実装者が機能追加やバランス調整を行う際の共通指針です。単発の表示改善ではなく、長期プレイでリーグ史と選手の物語が積み上がるゲームを目標とします。

## 基本方針

1. **記録をゲームの中心に置く**
   - 選手の今季成績、通算成績、年度別成績、歴代記録を一貫したIDで管理する。
   - 過去年度は当時の年齢、所属球団、役割、守備位置、OVR、能力値をスナップショットとして保存する。
   - 引退後も記録を削除せず、現役選手と同じランキング母集団で参照できるようにする。

2. **極端な記録を機械的に禁止しない**
   - 現実的な中心分布は守るが、まれな大記録やブレイクスルーは発生可能にする。
   - 年間本塁打数や受賞者数を固定上限として調整しない。
   - バランス検証では平均だけでなく、中央値、分位点、裾野、外れ値の頻度も確認する。

3. **AIは合理性と個性を両立させる**
   - 守備重視、打力重視、出塁重視、機動力重視、若手重視、ベテラン重視など複数の方針を持てるようにする。
   - 怪我、疲労、好不調、成長、移籍に反応する一方、不動の主力や固定打順も表現する。
   - AI判断は評価点・選出理由を開発時に監査可能にし、ブラックボックス化を避ける。

4. **表示は判断に必要な情報をその場で示す**
   - オーダー、守備配置、ローテーション、ブルペンでは、名前とOVRだけでなく年齢、今季成績、疲労、怪我を表示する。
   - モバイル表示では情報を削除するのではなく、優先順位を付けて折りたたみ・詳細表示へ逃がす。

5. **将来機能を塞がないデータ設計にする**
   - 一軍・二軍、二軍戦、年俸、契約、表彰、監督采配へ拡張可能な型を選ぶ。
   - 全打席ログを無制限保存せず、試合サマリーと詳細ログを分離する。
   - 保存形式を変更する際は旧セーブのマイグレーションを必ず用意する。

## 直近ロードマップ

### Phase 1: 盗塁処理と記録経路の修正

- 走者を真偽値ではなくPlayerとして塁上に保持する。
- 盗塁企図、成功、失敗を試合ログと個人成績へ確実に反映する。
- 走力、盗塁特殊能力、捕手肩力、投手能力、試合状況を盗塁判断へ反映する。
- 盗塁イベントが打席数・打数・投球数を誤って増やさないことを保証する。
- 単体テストと複数シーズンの分布検証を追加する。

### Phase 2: 球団情報・オーダー・ローテーションの情報密度改善

- 野手: 年齢、打率、本塁打、打点、盗塁、OPS相当、守備位置、状態。
- 投手: 年齢、防御率、勝敗、登板、先発、投球回、奪三振、WHIP相当、状態。
- 画面用途ごとに表示項目を最適化する。

### Phase 3: 名前生成の修正と拡充

- 不自然な姓・名、実在選手名の断片、外国人名の混入を整理する。
- 日本人名を頻度ウェイト付きで拡充する。
- 外国人名は出身地域ごとのプールを持つ。
- 同姓同名は許容し、内部IDで識別する。表示名への番号付加は行わない。

### Phase 4: 年度別成績とキャリア台帳

- `PlayerSeasonRecord` 相当の正式な型を導入する。
- 年度、年齢、所属、役割、守備位置、成績、OVR、能力値を保存する。
- 移籍・引退後も履歴を保持する。

### Phase 5: 歴代ランキング

- シーズン、通算、球団別のランキングを実装する。
- 達成年、年齢、当時の所属、現役・引退を表示する。
- 記録に固定上限を設けない。

### Phase 6: ゲーム開始時の架空リーグ史

- 現役選手のプロ年数と過去成績を能力曲線から生成する。
- 引退済みレジェンド、歴代記録、過去の優勝史を生成する。
- 過去全試合を逐次シミュレーションせず、統計生成で起動負荷を抑える。

### Phase 7: AI編成の監査と多様化

- 打順、守備、ローテーション、ブルペンの候補評価点を監査可能にする。
- 球団理念と監督傾向を導入する。
- 打順哲学、若手起用、固定選手、好不調への反応を分離して設計する。
- 監査基盤そのものは導入済みだが、実際の試合進行(打順・継投・代打などの意思決定)への適用は段階的に展開する方針とし、Phase 8時点ではまだ実戦には反映していない。

### Phase 8: 日別試合結果・ボックススコア・ニュース

日付ごとに全球団の試合結果を、実際のスポーツニュースサイト相当の粒度(イニングスコア、打者別・投手別成績、決定投手、注目記録)で保存・再閲覧できるようにした。

実装済み:

- 全試合について `GameSummary`(スコア、イニング別得点、被安打数、延長/引分/サヨナラ/完封の各フラグ、勝敗S投手の整形済みテキスト、代表見出し)を軽量サマリーとして必ず保存する。
- 自球団の試合、および「注目試合」(サヨナラ・延長・完封・8点差以上の大差・満塁本塁打・複数本塁打・4安打以上・二桁奪三振・完投のいずれかに該当)は、打者別・投手別成績を含む `GameBoxScore` を追加で保存する。該当しない試合は試合結果画面で軽量サマリーのみを表示し、「詳細ログは保存対象外」である旨を明示する。
- 打者成績(打順、守備位置、打数からAB/R/H/2B/3B/HR/RBI/BB/HBP/SO/SB/CS/併殺打、および試合終了時点の打率・本塁打・打点)と投手成績(登板順、先発/救援、勝敗S/ホールド、投球回・投球数・被安打・被本塁打・与四球・奪三振・失点・自責点、および試合終了時点の勝敗・セーブ・ホールド・防御率)は、その試合の直前時点までの通算成績スナップショットへ当該試合分を合算して算出する。保存後にシーズン成績が変動しても、過去の試合結果表示が遡って変わることはない。
- 決定投手の表示テキストは既存の勝敗S判定ロジック(`game.ts`)をそのまま利用し、「勝：山田(8勝3敗、防御率2.41)」の書式で整形する。
- 得点した走者のPlayer識別子(`AtBatLogEntry.scoredIds`)を新規に記録し、打者の得点(R)を正確に集計できるようにした。これ以外の確率ロジック・乱数消費順序は変更していない。
- 注目記録(本塁打・満塁本塁打・複数本塁打・三塁打・猛打賞・完投・完封・二桁奪三振・大差勝利・今季初本塁打・今季初勝利・サヨナラ/サヨナラ本塁打)を試合ログと試合直前の通算成績から検出し、試合詳細画面と自球団戦のニュース通知に反映する。ニュース通知は該当試合の `gameId` を保持し、通知から試合詳細へ直接遷移できる。
- 旧セーブ互換: `gameSummaries`/`gameBoxScores`/`Notice.gameId` はすべて省略可能なフィールドとして追加し、未定義の場合は空へマイグレーションする。

意図的に対象外(いずれも既存ロジックで正確に算出できないため、ゼロや推測値で偽装せず今回は実装していない。導入する場合は試合エンジンのイベントモデル自体を同時に拡張する):

- 一球速報、全打席の文章実況、守備交代・代打・代走の完全な履歴。
- 公式ルールに基づく失策判定、自責点の公式判定(現行は簡易近似式のまま)、投手交代時点の走者責任。
- 球場、観客数、試合時間、天候、打球方向などの視覚化。
- 個人記録・リーグ記録への接近/到達の自動検出。

なお犠打・犠飛はPhase 9で正式記録として実装したため、Phase 8時点の「対象外」からは外れている。

Phase 8はプロジェクトの最終フェーズではない。移籍市場・トレード、契約・財政(年俸/FA/契約更改)、怪我、表彰・タイトル、Phase 7で導入したAI監査基盤の実戦適用、バランス調整、UI改善は今後の課題として残る。

### Phase 9: 試合記録の整合性(公式記録ルールへの適合)

シーズン平均値(打率・防御率)だけを見る従来のbaselineテストでは検出できなかった、1試合の内部で野球のルールが破れている問題を修正した。全858試合を打席ログから再生して検証した実測値を根拠とする。

修正済み(括弧内は1シーズン858試合での実測、修正前 → 修正後):

- **併殺の成立条件**: 一塁走者がいない場面・2アウトの場面でも併殺が発生していた(併殺703件中、一塁走者なし420件・2アウトから239件 → いずれも0件)。併殺は「一塁が埋まっており2アウト未満」の場合のみ成立し、条件を満たさない打球は通常のゴロアウトへ再分類する。乱数の消費順序は変えていない。
- **投球回と実アウト数の不一致**: 2アウトからの併殺がイニングのアウト数を超えて投手成績へ加算されていた(不一致239アウト・207試合 → 0)。あわせて盗塁死を投球回へ算入し、盗塁企図が投球数を水増ししていた問題(1企図あたり+3球)も修正した。
- **走者の進塁判定**: 追加進塁の可否を「打者の走力」で判定していたため、鈍足の走者でも俊足打者が打てば進塁しやすかった。走者本人の走力で判定し、特殊能力「走塁センス」を反映する。
- **犠飛・犠打**: 三塁走者が生還したフライアウトが通常のフライアウト扱いで打数に計上されていた(犠飛0件・打率が不当に低下 → 犠飛188件)。犠打も打者のバント能力・特殊能力から成立するようにし(犠打92件)、犠打・犠飛はいずれも打席数に数え打数からは除外する。出塁率の計算式は元から犠飛を分母に含んでいたが、値が常に0だったため機能していなかった。
- **特殊能力の効果が名称と逆**: 投手のピンチ◎(po)・ピンチ×(px)・魂のエース(po_gold)・先頭打者○(ldo)・先頭打者×(ldx)が、名称から期待される方向と逆に奪三振率へ作用していた。打者のチャンス◎/×は元から正しいため変更していない。
- **引き分け試合の責任投手**: 引き分けでも勝利投手・敗戦投手が付与されていた(引き分け14試合すべてに付与 → 0)。引き分けでは勝敗・セーブ・ホールドをいずれも記録しない。
- **ピンチ判定**: 「走者がいて1アウト以上」という定義だったため、0アウト満塁が非ピンチ・1アウト一塁がピンチになっていた。得点圏(二塁または三塁)に走者がいるかどうかで判定する。
- **熟練度の球団間格差**: 自球団の累積成績のみを`simulateGame`へ渡していたため、CPU球団の選手は累積成績に存在せずシーズンを通して開幕時の熟練度に据え置かれていた。全12球団でリーグ全体の累積成績を渡す。バランス測定スクリプトも毎試合`{}`を渡しており全選手が開幕値のままだったため、実際のゲームと同じ条件へ揃えた。

バランス定数の再調整とbaseline更新:

- `AT_BAT_BALANCE.groundBall.doublePlayShare` を 0.1 から 0.75 へ変更した。従来は「あらゆる場面で」併殺が発生する前提で調整された値だったため、成立条件を正しくすると併殺が1シーズン148件(1球団あたり約12)まで落ち込む。現実的な水準(1球団あたり約98、リーグ計約1,174)へ戻すための再調整であり、打率には影響しない(単打の判定帯域は変えていないため)。
- 上記の修正群はシミュレーション結果を変えるため、`baseline/season-stats.json` を再生成した。NPB実測目標(`scripts/npb-targets.mjs`)は4項目すべて再生成後も範囲内である。

| ------------------------ | -------- | -------- | ------------ |
| 平均打率                 | 0.247077 | 0.248432 | 0.232〜0.257 |
| 平均防御率               | 3.098202 | 2.945392 | 2.21〜3.60   |

- 併殺が正しく走者を消すようになった結果、打点の分布が縮んだ(打点王平均 105.38 → 98.89、100打点以上 0.74人/季 → 0.53人/季、120打点以上 0.25 → 0.11)。打点王の水準自体はNPB実測(概ね95〜110)に整合するが、100打点到達者の人数は実際のNPBより少ない。これは併殺修正で新たに生じた問題ではなく、従来からある「個人成績の分散が実際より小さい」という性質が可視化されたものと考えられる。本塁打側の裾(40本以上 0.45 → 0.36、50本以上 0.11 → 0.06)は100シーズン中の発生回数が元々少なく、統計的な揺らぎと区別できない。

回帰テスト(`tests/game-record-consistency.test.ts`)を新設し、次を検証する。いずれも該当修正を戻すと失敗することを確認済み。

- 併殺が成立条件を満たす場面でのみ発生する
- 投手に記録されるアウト数が実際のアウト数と一致する
- 盗塁企図が打席数・打数・投球数を増やさない
- 犠打・犠飛が打席数に入り打数には入らない
- 得点者IDの総数がチーム得点と一致する
- 引き分けに責任投手が付かない
- 全12球団の選手が熟練度の入力に含まれる

未対応(設計判断が必要なため、Phase 9のスコープ外とした。**以下はPhase 10でほぼすべて解消済み**であり、残った項目はPhase 10末尾の「残る課題」に整理してある):

- **守備能力が打球結果へ反映されない**: 守備位置・守備力・肩力・守備範囲・エラー率はスタメン選定にしか使われておらず、同じ投打なら守備の巧拙で打球結果が変わらない。打球判定へ実際の守備選手を参照させる変更は、打球方向モデルとイベントモデルの再設計を伴う。
- **失策と自責点の公式判定**: 自責点は現在も打点から`RBI × 0.88`で近似している。失策・野選・暴投・捕逸を導入しない限り、失点と自責点を正しく分離できない。
- **継承走者の責任投手**: 塁上の走者がどの投手の責任で出塁したかを保持していないため、投手交代後の生還が現在の登板投手へ付く。
- **勝敗・セーブ・ホールドの公式ルール判定**: 勝利投手は「勝利チーム先発が15打者以上と対戦」、敗戦投手は「最も打点を許した投手」という簡易判定のままで、決勝点の責任投手とは一致しない。救援勝利も事実上発生しない。
- **未使用の特殊能力**: 定義されている39能力のうち、試合結果へ影響するのは25能力。バント○(bnt)と走塁センス(run)はPhase 9で有効化したが、初球○/×(fbo/fbx)、疲れにくい(tough)、鉄腕(iron)、勝ち運(win)、エース(ace)、リード術(ld_art)、強肩(strong_arm)などは依然として試合結果に作用しない。
- **捕手のリード能力の作用方向**: `ld`が奪三振率・与四球率・被本塁打率へ同じ方向の倍率を掛けているため、リードが良いほど四球も本塁打も増える。捕手能力として一貫した設計になっていない。
- **変化球の球種別パラメータ**: 球種ごとの`brk`(変化量)・`ctl`(制球)は打席判定に使われず、最も優れた変化球の総合値(`shr`)のみが奪三振率へ寄与する。
- **打者の変化球対応(cb)がインプレー打率へ影響しない**: `cf`(直球対応)のみがインプレー時の安打率へ寄与しており、`cf`と`cb`の効果が非対称。
- **死球が出塁率に含まれない**: `BatterStats`に死球の欄がないため、出塁率が公式式より低く出る。
- **得点差・イニング・終盤かどうかが打席確率に影響しない**: 投手交代や試合終了には使われるが、打席の確率そのものには渡されていない。
- **個人成績の分散が実際より小さい**: 上記のとおり100打点以上の到達人数などが実際のNPBより少ない。リーグ全体の平均は目標範囲に収まる一方で裾が薄く、突出したシーズンが出にくい。分布の裾を広げる調整は独立したバランス課題。

### Phase 10: 打席処理の階層化と公式記録への適合

Phase 9で見送った設計課題をまとめて解消した。打席結果を一度に決めていた平坦なモデルを段階的な判定へ組み替え、守備・失策・自責点・責任投手を組み込んでいる。

**打席処理の階層化.** 従来は三振・四球・死球・本塁打の確率を独立に出して1回の抽選で結果を選び、残りをインプレーとして振り分けていた。現在は7段階で決める。

1. 三振 / 四球 / 死球 / インプレー
2. 打球の質（ゴロ・ライナー・フライ・ポップ）
3. 打球方向（引っ張り・センター・流し）
4. その打球を処理する守備者の能力と突き合わせて 安打 / アウト / 失策、外野フライは本塁打判定
5. 安打なら単打・二塁打・三塁打
6. 走者ごとの進塁と本塁突入、外野からの補殺
7. 犠打・犠飛・野選・併殺・打点の公式記録への分類

本塁打は独立した確率ではなく打球段階で決まるようになった。長打力は「どの打球がスタンドまで届くか」に効き、球場・打球方向・投手の被本塁打耐性と結び付く。

**守備と失策.** `df`（守備力）と `fld`（投手守備）はこれまでスタメン選定にしか使われず、打球結果に一切影響していなかった。打球方向から責任守備位置を引き、その守備者の守備力とポジション適性で安打かアウトかが変わる。`bestLineup` は守備位置を重複・欠落させうるため、本職一致→適性あり→最も適性の高い控えの順にフォールバックする。失策は1球団あたり年間75前後（NPBの実測は80〜100）。

**自責点と継承走者.** 走者ごとに「誰が出塁させたか」「失策で出塁したか」を保持し、生還を出塁させた投手の失点として記録する。自責点は公式の再構成方式で判定し、失策がなければ成立していたアウトが3に達した後の得点と、失策で出塁した走者の得点を非自責とする。非自責点は全失点の8%程度。従来の `RBI × 0.88` という近似は廃止した。

**勝敗・セーブ・ホールド・ブロウンセーブ.** 公式規則に沿った判定へ置き換えた。先発は5回以上かつ降板時にリードしている場合に勝利投手、そうでなければ勝ち越し時点で投げていた救援投手へ。敗戦投手は相手が最後まで手放さなかった勝ち越し点の責任投手。セーブは3点差以内・同点走者が打席圏内・3回以上のいずれか。型に存在しながら一度も加算されていなかった `PitcherStats.bs`（ブロウンセーブ）を配線した。1シーズンで救援勝利が決着試合の26%、セーブ456、ホールド1球団74、ブロウンセーブ1球団16と、いずれもNPBの実勢に収まる。

**特殊能力.** 定義済み39種のうち8種（疲れにくい・鉄人・強肩・配球の妙・勝負強さ・対エース○・初球○/×）は生成・保存・表示され総合値にも加算されながら試合結果に一切影響していなかった。すべて有効化し、名前に反してゴロ率を上げていなかった「ゴロ打たせ○」も是正した。現在は39種すべてが試合に作用する。

**成績の分布.** リーグ平均だけでは「平均は正しいが誰も3割を打たない」状態を検出できないため、規定到達者ベースの分布指標を目標に追加した（3割打者数・40本塁打・100打点の到達人数、防御率2点未満の投手数、1球団あたり失策数、非自責点の割合）。`npm run diagnose` で1シーズン分の実測を確認できる。

| 指標                  | 実測   | 目標範囲     |
| --------------------- | ------ | ------------ |
| 平均打率              | .247   | .232〜.257   |
| 平均防御率            | 3.33   | 2.21〜3.60   |
| 年間本塁打            | 1,088  | 1,000〜1,200 |
| 盗塁企図/試合         | 0.44   | 0.30〜0.60   |
| 3割打者（規定）       | 13.3人 | 3〜18        |
| 100打点到達           | 6.0人  | 0.8〜7       |
| 防御率2点未満（規定） | 5.2人  | 1〜10        |
| 1球団失策             | 75.4   | 65〜110      |
| 非自責点の割合        | 8.3%   | 4〜13%       |

Phase 9で課題として残していた「個人成績の分散が実際より小さい」問題は解消した。100打点到達者は0.53人/季から6.0人/季になっている。

**残る課題.**

- 暴投・捕逸・ボーク・振り逃げ・守備妨害は未実装で、失策のみが唯一の守備の失敗である。
- 守備シフトや球場ごとの守備範囲差は表現していない。
- 代打・代走・守備交代の履歴は残らない。
- 一球速報と全打席の文章実況は対象外のまま。
- 個人記録・リーグ記録への接近/到達の自動検出は未実装。
- 移籍市場・契約財政・怪我・表彰・AI実戦適用は引き続き今後の課題。

### Phase 11: 継投・責任投手・サヨナラ・走塁の公式規則への適合

コードレビューで見つかった、記録（=物語の根拠）を誤らせる規則違反を修正した。

- **継投記録のスコア**: 投手交代時の登板・降板スコアが半イニング開始時点の値になっており、そのイニングの得点が反映されていなかった。これによりホールド・ブロウンセーブ・セーブ状況の判定が狂っていた。現在は交代時点の実スコアを記録する。
- **勝利投手**: 「最終的な勝ち越し点が入った時点で、勝利チームの記録上の投手」に付ける（公式規則9.17）。先発は5回以上が必要で、満たさない場合は最も効果的な救援投手に付ける。従来は、先発が降板後にリードを失い、その後の再逆転で勝ったときも先発に勝ちが付いていた。救援勝利は「最初の勝ち越し」を基準にしていた。
- **セーブ**（9.19）: 次の3条件のいずれかを満たす場合に限定した。
  - 3点以内のリードで登板し、1イニング以上投げる。
  - 同点の走者が塁上・打席・次打者にいる状況で登板する。
  - 3イニング以上投げる。
  - 従来は3点差で登板して1アウトだけ取ってもセーブになっていた。
- **サヨナラ**（9.06(f)）: 本塁打以外は、決勝点が入った時点で試合を終える。安打は、決勝走者が進んだ塁数までしか記録しない（三塁走者の生還なら単打）。従来は、打球で入った全得点と全打点を計上していた。
- **走塁**:
  - ゴロアウトで、押し出される走者が進塁しないまま残っていた。現在は押し出される走者が1つ進み、満塁なら三塁走者が生還する。
  - 内野フライ（popup）で三塁走者がタッチアップし、犠飛になっていた。
  - 無死からの併殺で三塁走者の得点が捨てられていた。現在は得点になり、打点は付かない。
- **延長12回打ち切り**: NPBの規定どおり、延長は12回までとした（従来は15回）。引き分けは1シーズン約4試合から約22試合になった。
- **日程の日付**: ローカル時刻で作った日付を `toISOString` で書き出していたため、日本時間では全日程が1日早くずれていた。月曜の休養日も実質日曜になっていた。日付計算をUTCに統一した。

ゴロアウト時の進塁が正しくなったことで得点環境が上がった。baselineを再生成した（100シーズン平均、修正前 → 修正後）。

| 指標                  | 修正前 | 修正後 | 目標範囲     |
| --------------------- | ------ | ------ | ------------ |
| 平均打率              | .2443  | .2442  | .232〜.257   |
| 平均防御率            | 3.27   | 3.50   | 2.21〜3.60   |
| 年間本塁打            | 1,153  | 1,144  | 1,000〜1,200 |
| 100打点到達           | 5.70人 | 6.95人 | 0.8〜7       |
| 防御率2点未満（規定） | 5.03人 | 3.37人 | 1〜10        |

防御率と100打点到達者は目標範囲内だが、上限に近い。進塁確率（`scoreFromThirdOnGroundOut` など）を下げても防御率はほぼ動かなかった（3.50 → 3.50）。得点の増加は、規則上必須の押し出し進塁によるものである。したがって、得点環境の再調整はインプレー打球の安打率など打撃側の定数で行う、独立したバランス課題として残す。

回帰テストを追加した（`tests/game-record-consistency.test.ts`、`tests/engine.unit.test.ts`）。いずれも修正前の実装で失敗することを確認済み。

- 登板時スコアが直前の実スコアと一致する。
- 勝利投手が勝ち越し時点の記録上の投手である。
- セーブが3条件のいずれかを満たす。
- 本塁打以外のサヨナラは1点差で終わる。
- ゴロアウトで一塁走者が残らない。
- 内野フライの犠飛がない。
- 延長は12回まで。
- 日程がタイムゾーンに依存しない。

### Phase 12: おまかせ進行と長期バランス

「シーズンを飛ばして世界を眺める」遊び方のために、年単位の自動進行を加えた。あわせて、何十年も進めたときに初めて見える問題を修正した。

**おまかせ進行.** 概要は次のとおり。

- ダッシュボードとポストシーズン画面に「1年／5年／10年進める」を置いた。
- 残りのレギュラーシーズン、CS・日本シリーズ、オフシーズンを連続で実行し、1年ごとに自動保存する。
- オフシーズンは `runFullOffseason` で全球団をCPUが編成する。自球団も対象で、戦力整理・FA・外国人・順位順のドラフト・定年を行う。自球団がトレードで放出されることはない。

従来は、1年進めるのに判断の要らないクリックが9回あった。自球団はCPUの整理の対象外だったため、放置すると毎年ロースターが増えていた。

**退団選手の記録保持.** オフシーズンに退団した選手を `retiredPlayers` に残すようにした。対象は引退・自由契約・外国人の退団・MLB移籍のすべて。従来はユーザーが手動で引退させた選手しか残らず、CPUが整理した選手は記録から消えていた。

**長期インフレの原因と修正.** 25年ドリフトを測定し、原因を特定した（`npm run drift`）。

- **変化球が成長しない.** 変化球の球威（`shr`）は生成時の値のまま成長も衰退もしなかった。一方、打者の変化球対応（`cb`）は成長する。18歳で入団した投手は一生、高卒時の変化球を投げ続けるため、生成時の投手が引退するにつれて打高が進んでいた（防御率 3.6 → 4.3、本塁打 1,100 → 1,600）。
  - 現在は制球とノビの成長・衰退に合わせて変化球も変化し、25年間の防御率は横ばいになった。
- **投手OVRが変化球を含まない.** 変化球は奪三振の約4分の1を左右するのに、投手OVRに含まれていなかった。そのためCPUのローテーション・整理・ドラフト・トレードが、実際の投手の実力を見誤っていた。OVRに最良の変化球を加えた。
- **開幕時が定常状態と別の時代になっている.** 生成直後のロースターは、長期の定常状態よりOVRが約12低い。さらに生成時の記録級スターが先に引退するため、10〜16年目にスターが減る谷がある。
  - 新しい世界は、試合なしのオフシーズンを20回実行してから開幕する（`initSettledTeams`）。
  - バランスの基準値（`baseline/season-stats.json`）も、この定常状態のリーグで測るようにした。
- **ベテランの滞留.** 定年（42歳）と「35歳以上かつOVR55以下」以外では、ベテランが引退しなかった。
  - 33歳以上は年齢に応じた確率で自発的に引退するようにした。スター（OVR80以上）とレジェンド（OVR100以上）は引退しにくい。
  - 引退はその冬の放出枠を使うので、ロースター人数は変わらない。
  - 25年後の平均年齢は 28.6 から 27.9 に下がった。
- **抑え投手の過剰起用.** 抑えを負けている9回にも投入していた。9回以降の同点または3点差以内のリードに限定した。
- **ドラフトの性能.** CPUのドラフト指名が、並べ替えの比較ごとにロースターを走査していた（オフシーズン処理時間の83%）。候補ごとに1回だけ評価するようにし、指名結果は同一のまま約3倍速くした。

**再調整.** 定常状態のリーグに合わせて定数を調整した。

- 本塁打の基礎確率とパワーカーブ
- インプレー打球の安打率
- 盗塁企図
- 救援投手の疲労
- 奪三振への能力の効き幅

100シーズン平均は次のとおり（すべてNPB目標範囲内）。

| 指標         | 値    |
| ------------ | ----- |
| 打率         | .243  |
| 防御率       | 3.43  |
| 年間本塁打   | 1,065 |
| 30本塁打以上 | 2.1人 |
| 3割打者      | 9.2人 |
| 防御率1点台  | 2.4人 |

**残る課題.** 25年ドリフトの `competition` を見ると、勝率の球団間の標準偏差が約0.11ある。NPBの実勢はおよそ0.05〜0.07で、それより大きい。シードによっては、同じ球団が10〜20年連続で優勝する王朝が生まれる。

原因は3つある。

- 本物のFA移籍がない（FA市場は毎年生成される架空の選手）。
- 経済的な制約がない。
- 全CPU球団の編成方針が同じ。

次の段階で、軽い経営要素と日本人選手のFA、球団ごとの編成方針によって解消する。

### Phase 14: 年俸・FA・球団予算（軽い経営要素）

選手が球団を移る物語を、生成された架空のFA選手ではなく、リーグにいる実在の選手で起こすようにした。経営要素は、放置して眺める遊び方を邪魔しない軽さにとどめた。

**契約と年俸（`src/engine/contracts.ts`）.**

- 選手に年俸・契約年数・一軍在籍年数を持たせた。
- 年俸はOVRと年齢から決まる市場価値が基準で、3億円を超えると伸びが緩やかになる。FA権を取るまでは、在籍年数に応じてその一部しか受け取れない。
- 契約更改は成績で上下し、NPBの減額制限（1億円超は40%、以下は25%）に従う。予算を超えている球団は昇給を抑える。そのため、年俸総額は数十年進めても予算の近くにとどまる。
- 一軍在籍年数は、そのシーズンの出場（野手40試合または120打席、投手20登板または50回）で数える。

**FA（`src/engine/freeAgency.ts`）.**

- 国内FA権は高卒8年、大卒・社会人7年、海外FA権は9年で得る。行使すると4年後に再取得する。
- 権利を持つ主力が、年俸の不足・負け越し・球団の予算不足に応じてFA宣言する。宣言しなければ、多くは複数年契約で残る。
- 各球団は予算の範囲で入札し、競合すると提示額が上がる。
- A・Bランク（元球団の年俸上位3人・10人以内）の選手が移籍すると、元球団はプロテクト外（上位28人以外）から人的補償を1人獲得する。
- 誰も獲得しなかった選手は宣言残留する。
- 従来の架空FA選手は「自由契約・独立リーグ・MLB帰り」の選手として市場に残した。
- FAや流出で人数が足りなくなった球団は、育成選手を支配下登録して補う。

**MLB移籍と復帰.**

- OVR95以上の主力は、海外FA権かポスティングでMLBへ移籍することがある。
- 海外にいる間も年を取って成長・衰退し（`overseasPlayers` に保存）、2年目以降は年齢とともにFA市場に戻りやすくなる。戻るときは元の球団に引かれ、再びMLBへは行かない。
- ユーザーが編成するオフシーズンでは、自球団がポスティングで選手を放出することはない。

**予算.**

- 本拠地の市場規模（`TINFO.bd`）が基準。前年の勝率とポストシーズン進出の収入で、少しずつ増減する。
- 予算の余力がない球団はFA選手を獲得できない。

**画面.**

- FA画面に予算・年俸総額・獲得後の余力を表示した。候補ごとに元球団・ランク・提示額を示し、予算が足りない選手は獲得できない。自球団から宣言した選手は、ここで再契約できる。
- 選手詳細に年俸・契約残り・FA権（あと何年か）を表示した。
- 球団情報に予算、高額年俸、今オフのFA候補を表示した。
- 年度総括の「主な移籍」に、MLB移籍・MLB復帰・FA移籍・人的補償・FA残留を加えた。
- 自球団の関わる移籍はチームニュースに残る。

**バランス.**

- 従来、CPUの入札上限は `bd × 100`（約7,700万円）の固定値だった。そのため、OVR65前後を超える外国人・FA選手はほぼ獲得されていなかった。
- 予算制に変わって獲得されるようになり、リーグの投手力（特に救援）が上がった。
- 打撃側（安打率、本塁打のパワーカーブ）と盗塁企図を再調整した。
- MLB流出で最上位層（OVR100以上）が薄くなるため、長期育成監査の下限を4.5人に下げた。代わりに、OVR85以上が30人以上いることを確認する。

100シーズン平均は次のとおり（すべてNPB目標範囲内）。

| 指標         | 値    |
| ------------ | ----- |
| 打率         | .243  |
| 防御率       | 3.46  |
| 年間本塁打   | 1,109 |
| 30本塁打以上 | 2.6人 |
| 3割打者      | 8.5人 |

25年ドリフト（4シード）の年平均は次のとおり。

- FA宣言：8〜10人
- 他球団への移籍：4〜7人
- MLB移籍：0.6〜1.4人

**残る課題：戦力の均衡.** FA・予算を入れても、勝率の球団間標準偏差は大きくは変わらなかった。

- 4シードで0.10〜0.12。導入前は0.11〜0.12。
- シードによっては、同じ球団の10年以上のリーグ優勝がまだ起こる。

原因を調べた結果は次のとおり。

- 定常リーグの球団間の戦力差（打線・先発・救援の平均OVRの標準偏差）は、選手を無作為に配り直した場合より小さい。つまり、CPUの編成は既に戦力を均している。
- 原因は2つある。
  - 能力分布の裾が厚い：上位1%がOVR100前後、中央値が48。
  - 試合エンジンが戦力差を得点差へ強く変換する：1シーズンのチーム得点が約300〜700点に広がる。NPBの実勢は約400〜600点。
- 次の「球団ごとの編成方針」では、この変換の強さも併せて扱う。

### Phase 15: 戦力均衡と球団ごとの編成方針

Phase 14で残った「強い球団が勝ち続ける」問題を、原因ごとに直した。リーグ全体の得点水準は変えず、強弱の差だけを縮める方針。

**計測（`npm run parity`）.** `scripts/parity-probe.ts` は、定常リーグを1シーズンずつ試合単位で回し、次を出す。

- 勝率の標準偏差
- チーム得点・失点の幅
- 守備・パワー・コンタクト・投手陣の平均が、得失点を1ポイントあたり何点動かすか

調整前は、守備1ポイントが年間約9点の失点差を生んでいた。一方、先発陣のOVRは1ポイントあたり約1点しか効いていなかった。25年ドリフトの `competition` にも、チーム得点の幅を記録するようにした。

**差の効き方を弱めた.**

- 守備：打球が安打になる確率への守備の効きを半分にした（`defenseScale` 240 → 480）。基準をリーグ平均の守備（`defenseReference` 63.5）に移し、平均的な守備での安打率は変えていない。
- パワー：本塁打のパワーカーブの中域を緩めた（`powerCurveScale` 16 → 18）。
- 投手：奪三振の能力効きを、中域では少し緩く、両端では広くした（`ratingEffectSoftness` 0.16 → 0.2、`maximumRatingEffect` 0.055 → 0.08）。チーム平均の差は縮め、エースの突出は残す。
- 基準の安打率と本塁打率を戻し、打率・本塁打の水準を保った。

**予算の差を縮めた.** 最長連覇していたのは巨人・ソフトバンク・阪神で、どれも資金力の大きい球団だった。予算の市場規模による差（`budgetPerBd` 6000 → 3000）と、成績による増減の幅（0.8〜1.3倍 → 0.88〜1.15倍）を縮めた。

**球団ごとの編成方針（`src/engine/clubPlan.ts`）.** CPU球団は毎オフ、前年の勝率と主力15人の平均年齢から方針を決める。

- 勝負：FA入札を強める。トレードで今の戦力を上げる。
- 再建：27歳以下にだけ積極的に入札する。トレードで年齢を下げる。整理では若手を残す。
- 中庸：どちらにも寄せない。

あわせて、球団ごとのチームカラー（`teamStrategyFor` の長打・機動力・守備志向）を、野手の獲得評価に少しだけ反映した。球団情報には「チームカラー」と「今の成績なら○○方針」を表示する。おまかせ進行では、自球団の方針をチームニュースに残す。

**結果.**

| 指標                           | 調整前     | 調整後       |
| ------------------------------ | ---------- | ------------ |
| 勝率の標準偏差（25年×4シード） | 0.10〜0.12 | 0.074〜0.099 |
| 最長リーグ優勝連続             | 最大18年   | 最大9年      |

100シーズン平均は、打率.245、防御率3.47、本塁打1,106、30本塁打以上2.1人、3割打者8.8人、防御率1点台1.0人で、すべてNPB目標範囲内。ただし30本塁打以上と防御率1点台は下限ぎりぎりで、個人成績の裾とチーム間の差は引っ張り合う。

### Phase 16: 表彰・殿堂・球団史・記録ウォッチ

長く進めた世界の歴史を、あとから読み返せるようにした。

**表彰（`src/engine/honors.ts`）.** シーズン終了時に、両リーグの表彰を選ぶ。

| 表彰               | 選び方                                                                 |
| ------------------ | ---------------------------------------------------------------------- |
| MVP                | 規定到達者のうち最も価値の高い選手。リーグ優勝球団の選手は少し加点する |
| 新人王             | 一軍在籍0年の日本人選手から選ぶ                                        |
| ベストナイン       | 各守備位置と外野3人、投手                                              |
| ゴールデングラブ賞 | 各守備位置で、守備力・適性・肩を評価する                               |

- 価値は、出塁率と長打率を出場機会で重み付けし、守備位置の希少性を加えた簡易的な得点換算で測る。投手は防御率と投球回、セーブ・ホールドで測る。
- 表彰は `honorHistory` として保存する。統計タイトル（`awardHistory`）とは分けている。AIニュースの事実パケットを変えないためである。
- 年度アーカイブには、表彰がある年だけ書く。そのため、既存の年のリビジョンは変わらない。
- 表彰は年度総括と選手詳細に表示する。

**記録タブ（`src/state/history.ts`）.** 保存済みの事実から毎回組み立てる。新しいデータは保存しない。

- **球団史**：年度別の順位・勝敗・日本一を並べ、リーグ優勝と日本一の回数を数える。在籍中の成績を合計した球団通算記録（安打・本塁打・盗塁・勝利・セーブ・奪三振）、歴代MVPとタイトルも出す。
- **殿堂**：引退選手が対象。次のいずれかを満たせば殿堂入りとする。MLBでプレー中の選手は除く。
  - 名球会の基準（2000安打・200勝・250セーブ）
  - 400本塁打または2500奪三振
  - MVP 2回以上
  - 1000試合以上出場し、タイトルとベストナインを合わせて8回以上
- **記録ウォッチ**：現役選手のうち、通算安打・本塁打・盗塁・勝利・セーブ・奪三振の節目が近い選手を出す。

### Phase 17: 簡易一軍登録枠

一軍・二軍の区別は以前からあったが、人数の上限がなく、全員が一軍扱いだった。救援投手の起用は二軍の投手も対象にしていた。

**登録枠（`src/engine/activeRoster.ts`）.** 一軍は31人（投手15・野手16）まで。

- 選び方：
  - 投手：先発6人、抑え2人を入れ、残りを救援で埋める。疲れた救援は新しい投手と入れ替える。
  - 野手：打線、捕手2人、各守備位置を1人ずつ確保し、残りを能力順で埋める。
  - 故障者は二軍に落とす。
- 開幕時に全球団を登録する。自球団も含む。
- CPU球団は、毎週と、一軍の選手が故障したときに見直す。救援投手の疲労がたまったときも見直す。
- おまかせ進行では、自球団も同じように管理する。
- 手動で入れ替える「一軍・二軍」タブでは、31人を超えて一軍に上げられない。登録人数も表示する。
- 試合中の救援は、一軍の投手から選ぶ。二軍の投手は、一軍の救援がいないときだけ使う。
- バランス計測（基準値、ドリフト、パリティ計測、診断、投手起用テスト）も、同じ週ごとの入れ替えを通して試合を回す。

**救援の起用.** 一軍の救援が8〜9人に絞られ、同じ投手の登板が年100試合を超えた。次の3点で直した。

- 3連投を避ける（`maximumConsecutiveDays`）。
- 抑えは9回から投入する（従来は8回から）。
- 休める救援が尽きたときは、登板中の投手がもう少し長く投げる。先発は30球、救援は18球まで。

**再調整.** 次の値を調整した。

- 安打率
- 本塁打の基礎確率
- 奪三振の能力効きの両端（`maximumRatingEffect` 0.1、`ratingEffectSoftness` 0.24）

100シーズン平均は、打率.243、防御率3.46、本塁打1,148、30本塁打以上2.3人、3割打者8.7人、防御率1点台1.0人で、すべてNPB目標範囲内。

25年ドリフトの勝率の標準偏差は0.087〜0.108。控え選手が試合に出なくなったため、Phase 15よりやや広い。

### Phase 18: AI編成の統一・試合の見せ方・画面構成

**AI編成の統一.** 自球団の「AIで編成」系ボタンが、CPU球団と同じAI（`strategicBestLineup`・`strategicPitcherPlan`・`assignActiveRoster`）を使うようにした。

- オーダーは `recommendedLineup`、投手陣は「AIで投手陣を編成」、一軍登録は「AIで一軍を登録」。
- 保存したオーダーは、スキップ中も使う。故障・二軍落ち・退団した先発は、同じ打順・同じ守備位置で1人ずつ入れ替え（`repairLineup`）、入れ替えた内容をお知らせに出す。黙って全体を組み直すことはしない。
- 投手編成が空のときは「試合ごとにAIが判断」。次の試合でもスキップでも同じ扱いにした。

**試合の見せ方.** 自球団の直近10試合は、プレイバイプレイ（`GamePlayLog`）を保存する。

- 半イニングごとに、打席結果・アウト・走者・継投・バント・盗塁を起きた順に並べる。
- 「1イニングずつ観る」で、攻撃ごとに試合を追える。
- ダッシュボードに「直近の試合」カードを置き、スキップ後に古いボックススコアが残る問題をなくした。
- ポストシーズンの各試合もボックススコアを残し、シリーズ画面から開ける。

**画面構成.** シーズン画面の13タブを、ホーム・チーム・試合・リーグ・記録の5分類にまとめた。

- 分類ごとに最後に開いたタブを覚える。タブは ←→・Home・End で移動できる。
- 「試合」に日程タブを追加した。自球団の試合を月ごとに並べ、勝敗・スコア・交流戦・振替を示す。結果から試合詳細を開ける。
- 選手一覧の今季成績に、OPS、投球回、奪三振、WHIP、セーブ・ホールドを加えた。
- 英語のままだった見出し（Next Game、Squad Board など）を日本語にした。
- `window.confirm` をすべて、テーマに合わせた共通の確認ダイアログ（`ConfirmDialog`）に置き換えた。削除や上書きのような取り消せない操作では、最初のフォーカスを「キャンセル」に置く。

**スキップの区切り.** 週・月スキップが自球団の試合数で止まると、同じ日の他球場の試合が未消化のまま残っていた。止まった日の残り試合も消化するようにした。

**スタイル基盤.** 見た目を変えずに、スタイルの置き場所を整理した。

- 画面ごとのCSSを `src/styles/` に分け、`main.tsx` から一括で読み込む。`phaseB.css` は `player-tables.css` に改名した。
- 文字サイズのトークン（`--text-2xs`〜`--text-2xl`）と、共通レイアウト（`.stack`、`.card-grid`）を追加した。
- インラインスタイルの多かった7ファイル（HistoryTab、RosterTable、GameDetailView、PostseasonScreen、DashboardTab、GameResultsTab、YearReviewTab）を、クラスに移した。208か所が23か所になった。残りは球団色など、実行時に決まる値だけ。
- 乱数と時刻を固定したブラウザで、変更前後の14画面とポストシーズン画面を撮り比べ、ピクセル単位で一致することを確かめた。
- 幅390pxで全タブを計測し、ページの横はみ出しがないことを確認した。唯一横スクロールが必要だった順位表は、スマホでは「直近10」「内訳」列を隠して収めた。

### Phase 19: 球場・スコアボード風の見た目

ナイター球場とスコアボードを軸に、画面の印象と遊びの流れを作り直した。

- タイトル画面：ナイター球場の背景に、スコアボード風のロゴを置いた。3つのセーブ枠は、どの球団の何年目かが分かるカードにした。JSONの書き出し・読み込みは「セーブの管理」に畳んだ。
- 球団選択：リーグごとに3列で並べ、初期地力から「優勝候補」「Aクラス争い」「上位進出を狙う」「下剋上に挑む」を示す。
- シーズン画面のヘッダー：電光掲示板のように、順位・勝敗・勝率・差・連続・残り試合を表示する。新しいゲーム・タイトルへ・設定は「メニュー」にまとめた。
- 試合進行バー：次の試合・1週・1か月・全試合を、どのタブにいても画面下から押せる。進めた直後に、勝敗や期間の成績を結果表示で知らせる。
- ダッシュボード：次の試合を主役にした。両球団の成績と予告先発（`probableStarter`。`simulateGame` と同じ選び方）を示し、直近の試合を並べる。そのあとに、自リーグの順位（自球団の行を強調）、スコアボード風の打順、お知らせ、おまかせ進行を置いた。

### Phase 20: ペナントの緊張感

- `pennantRace`：首位球団のマジックナンバーを、直接対決の残り試合も含めて最悪の場合で計算する。あわせて、優勝・CS進出の決定と、それぞれの可能性消滅を判定する。マジックは残り60試合を切ってから点灯する（それ以前は「M130」のような意味のない数字になるため）。
- ダッシュボードの「ペナントレース」：見出し（マジック、首位で何差リード、首位と何差、可能性消滅、リーグ優勝）、CS圏の状況、終盤の天王山・直接対決の予告を示す。ゲーム差の推移グラフは、自球団だけを球団色で描き、他球団は灰色。ホバー・キー操作で各日付の値を読め、表でも見られる。
- 「ペナント」のお知らせ：マジック点灯・優勝決定・CS進出決定・可能性消滅を、それぞれ一度だけ知らせる。1か月スキップで試合結果のお知らせが大量に出ても埋もれないよう、先頭に置く。

### Phase 21: 目標と評価

- 開幕時に、オーナーが戦力のリーグ内順位から目標を示す（リーグ優勝／CS進出／Aクラス入り／4位以上／最下位脱出）。ペナントレースのカードに、目標と今の位置（達成圏か）、信頼度を示す。
- ポストシーズン後に、最終順位と目標の差、日本シリーズ進出・日本一の加点からS〜Dで評価する。評価に応じて、オーナーの信頼度（0〜100）と来季予算（±4%、リーグの予算の範囲内）が動く。解任はしない。信頼度が低いと「解任の危機」と表示する。
- 年度総括に、その年の評価をスコアボード風に表示する。球団情報に、監督の歩み（信頼度と毎年の目標・順位・評価）を表示する。

### Phase 22: 選手の人気と推し選手

- 選手ごとの人気（0〜100）を持たせた。初期値は能力から計算する。毎オフ、その年の成績、タイトル、表彰（MVPは+14）、記録・節目、日本一で上下する。出場が少ない年は、能力相応の水準へ戻っていく。
- 人気の影響：
  - 球団の収入：ファン人気（人気上位10人の平均）がリーグ平均からどれだけ離れているかで、最大±5%。
  - 観客動員：ファン人気・順位・曜日で決まり、同じ試合なら毎回同じ人数になる。
  - お知らせ：自球団の選手の人気急上昇やスター誕生を知らせる。
- 表示：選手詳細の人気表示、ランキングの人気選手、球団財務のファン人気と観客動員（平均）。
- 推し選手：選手詳細の「☆推し」で登録すると、ダッシュボードで今季の成績と人気を追える。移籍しても、引退・海外移籍しても一覧に残る。

### Phase 23: デバッグ編集を自由に

- 数値は入力中は自由に打てて、フォーカスが外れたときかEnterで確定・範囲内に丸める（Escで元に戻す）。以前は1打鍵ごとに丸めていたため、「25」を打とうとすると「2」の時点で15になっていた。
- 球速はkm/hで入力する。能力値は現在値1〜130、潜在値は潜在クラスに関係なく1〜150まで。
- 特殊能力を外すと、保存しても戻らない。守備適性を0にすると、その守備位置を外す。
- 追加した編集欄：名前、主守備位置／役割、投打、人気、年俸、契約年数、FA年数、故障日数、疲労、一軍登録、気質、球種（種類・球威・変化量・制球、追加・削除）。
- 保存すると自動保存される。引退した選手や海外へ移った選手も編集できる。

### Phase 24: 次の試合をスキップと同じ経路に

- 「次の試合」は `applySkip(current, 'next')` で進める。自球団の試合より前のリーグ戦、その試合、その日の残りを消化するので、1試合ずつ進めてもスキップしても、日の区切りが常に揃う。
- 新規ゲームと新シーズンでは、開幕日の試合を事前に消化せず、未消化のまま始める。

### Phase 25: 人気の要因を広げ、気質を加える

- **アマチュア時代の知名度**：新人の人気に上乗せされ、プロ4年目までに薄れていく。対象は次のとおり。
  - 知名度の段階
  - 甲子園（全国大会）の成績。優勝・準優勝は高く加算する。
  - 大学日本代表、都市対抗、大学での表彰
  - 規格外素材
  - ドラフト1位（`draftRound` を選手データに保存するようにした）
- **シーズン中の上昇**：次の活躍で人気がすぐ上がる。上限はシーズンごとに+15まで。
  - サヨナラ本塁打 +3
  - サヨナラ・満塁本塁打・完封 +2
  - 二桁奪三振・1試合複数本塁打・完投 +1
  - 記録・節目 +3
- **在籍8年以上の選手**：試合に出られない年でも人気が落ちにくい。
- **気質**（大舞台に強い／平常心／注目で力む）
  - 選手IDから決まり、割合はおよそ20%／65%／15%。選手詳細に表示し、デバッグで変更できる。
  - 人気が50を超えると効果が出はじめ、打者と投手の力関係が最大±2%動く。7回以降の1点差以内とポストシーズンでは2倍になる。
- **バランス調整**：防御率1点台の人数をNPB目標の範囲内に保つため、奪三振の能力効果の上限を0.1から0.102に上げた。基準値は撮り直した。

### Phase 26: 記事の事実を充実させる

- **シーズン総括**：記事の文はすべて事実から作る（決まり文句のCOLOR文は廃止）。載せる事実は次のとおり。
  - タイトル獲得者と最終ゲーム差
  - 優勝を決めた日（`clinchDate`）
  - 主催試合の平均観客動員
  - 自球団の場合、オーナーの目標と評価
- **故障記事**：離脱前までの今季成績を載せる。
- **新しい出来事記事**：ドラフト1・2位ルーキーのプロ初出場（debut）と、初の個人タイトル（breakthrough）。
- **引退記事**：引退時の年齢を載せる。
- **成長記事**：内部値のOVRではなく、伸びた・落ちた能力の名前で伝える。
- **選手名鑑**：シーズン中の今季成績、人気、気質を加えた。潜在能力・成長タイプはAIに渡す事実から外した。
- **AI文の検証**：数字の検証で、助数詞の前の漢数字も数値として照合する。「ファン」「観客」は、観客動員か人気の事実を引用した文でだけ使える。

### Phase 27: ライブ観戦と効果音

- **ライブ観戦**：自球団の試合を、記録済みの打席ログから1打席ずつ再生する（試合をやり直すのではなく、決まった結果を見せる）。
  - スコアボードのランプ、BSO、球場図（打球の軌道・走者・守備位置）、実況テロップ。
  - 本塁打・逆転・勝ち越し・同点・サヨナラ・ゲームセットで大きな文字、本塁打とサヨナラで画面の揺れ、サヨナラと勝利で紙吹雪。
  - 再生・一時停止、1×・2×・4×、次のイニング、結果まで。
  - 入口：結果フラッシュ、試合詳細、設定「次の試合をライブで観戦」（次の試合のあと自動で開く）。
- **打席ログ**：捕球した野手（`fieldingSlot`）、打球方向（`spray`）、打席後の塁（`basesAfter`）を残し、保存用のログにも打球の種類と球数を載せる。乱数は増やしていないので、基準比較は変わらない。古いセーブのログは説明文と前後の塁から補って再生する。
- 球数の見せ方（ボール・ストライク・ファウル）は試合IDと打席から決まる表示専用の並びで、エンジンの乱数は使わない。
- **効果音**：Web Audio で合成（打球音、ミット、歓声、大歓声、ため息、オリジナルのオルガン、サイレン、チャイム）。音声ファイルは使わない。既定はオフで、設定で音量と試し聴き。
- **演出を控えめに**：揺れ・紙吹雪・アニメーションを止める。OSの「動きを減らす」設定が既定値になる。

### Phase 28: 号外・紙面

- **リーグ優勝の出来事**（`pennantClinch`）：スキップの前後で優勝が決まった球団を、決定日・その日の勝敗・2位とのゲーム差・残り試合・その日の試合の結果とともに記録する。全文が事実の記事になり、ニュースでは重要度の高い「カバー」扱い。
- **紙面**：日本一・リーグ優勝・記録・表彰の記事を、架空紙「ダイヤモンド新報」の一面として開ける。縦書きの大見出し（明朝体 Shippori Mincho B1）、見出し・リード・本文は記事そのもの（AI記事ならAIの文）から組むので、記事にないことは載らない。スマホでは横書きに切り替える。
- **画像で保存**：Canvas に一面を描き直して PNG で保存（新しい依存なし）。
- **入口**：ニュースの「紙面で読む」、自球団の優勝・日本一のときのダッシュボードとオフ画面の号外バナー（開くか×で消える）。

### Phase 29: コネクタで作った一枚絵

- Gamma の画像生成で架空の球場のイラストを4枚作り、WebP にして同梱（出所と加工は `docs/asset-credits.md`）。
- 1枚目は背景の看板が実在企業のロゴに似ていたため、該当箇所をぼかしてから使っている。以後の生成では看板を無地にするよう指示した。
- **季節の背景**：シーズン画面の上部を、5月までは桜のデーゲーム（ライトテーマでも表示）、6月以降は夜の照明、ポストシーズンとオフはスコアボードの夜景に切り替える。
- **紙面の写真**：日本一は紙吹雪の球場、リーグ優勝は照明の球場、記録・表彰はスコアボード。

## 実装時の完了条件

各Phaseは、コードが動くだけでは完了としません。

- 型と保存形式が将来拡張を妨げない。
- 旧セーブへの影響を確認する。
- 単体テストまたは回帰テストがある。
- バランスに関わる変更は複数シーズンで分布を確認する。
- UI変更はデスクトップとモバイルの双方で確認する。
- 実装理由と検証方法をPR本文に残す。

試合エンジンに触れる変更では、シーズン平均の検証(`baseline/season-stats.json`)だけでは不十分です。`npm run diagnose` で1シーズン分の試合を打席ログから再生し、ルール違反の発生件数を実測できます。平均打率や平均防御率が目標範囲に収まっていても、1試合の内部では走者のいない併殺や投球回の過大計上といった矛盾が同時に成立しうるため(Phase 9で実際にそうなっていた)、`tests/game-record-consistency.test.ts` のような「試合内で必ず成り立つ条件」の検証を併せて用意してください。新しい不変条件を追加したら、該当する修正を一時的に戻すとテストが失敗することまで確認します。
