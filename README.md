# pennant-sim

React 18 + Babel Standaloneで動作していた単一HTML版を保持しつつ、Vite + React + TypeScriptへ段階的に移行するプロジェクトです。

## 必要環境

- Node.js 22
- npm

## セットアップ

```bash
npm install
npm run dev
```

Vite版は開発サーバーのURLで起動します。従来版は `/legacy/index.html` から開けます。

## 品質チェック

```bash
npm run lint
npm test
npm run build
```

`npm test` はNode標準テストによるengine・保存移行テストと、100シーズンのbalance baseline比較を実行します。GitHub Actionsではpushおよびpull requestごとに `lint → test → build` を必須実行します。

## GitHub Pages

`main` ブランチへのpush時に、`.github/workflows/deploy-pages.yml` がViteアプリをビルドし、`dist/` をGitHub Pagesへデプロイします。Viteの公開パスはリポジトリ名に合わせて `/pennant-sim/` に設定しています。

初回利用時は、リポジトリ画面で次の手動設定が必要です。

1. `Settings` を開く
2. `Pages` を開く
3. `Build and deployment` の `Source` を **GitHub Actions** に変更する

この設定はリポジトリ設定側の操作であり、コードやPull Requestからは変更できません。

品質確認用の `.github/workflows/ci.yml` とPages公開用workflowは分離しており、前者はlint・test・build、後者はmainのビルド成果物の公開だけを担当します。

## TypeScriptエンジン

Phase Bでは、旧版のデータ定義とゲームロジックを型付きモジュールへ移植しています。

- `src/data/`: 球団、選手名、OVR係数、育成係数、特殊能力、確率定数
- `src/engine/types.ts`: Player、Team、GameState、AtBatResult、成績などの型
- `src/engine/atBat.ts`: 打席結果と走者進塁
- `src/engine/game.ts`: 半イニング、試合進行、試合後イベント
- `src/engine/season.ts`: 日程、順位、CPU試合スキップ
- `src/engine/growth.ts`: 年間成長と覚醒
- `src/engine/playerEvents.ts`: シーズン中覚醒、怪我、復帰処理
- `src/engine/market.ts`: FA・外国人市場とCPU間トレード
- `src/engine/draft.ts`: ドラフト候補生成、指名順、CPU指名
- `src/engine/offseason.ts`: CPU球団の整理から補強までの共通オフシーズン進行

旧版の `accumulatedGlobal` に相当する状態は新エンジンには存在しません。習熟度計算に必要な成績は、`simulateGame`、`simHalf`、`simCpuUntilNext`、`skipGames` へ明示的に渡します。

日程生成では雨天順延を当初日と順延元の両方で記録し、同一カードの将来日へ組み込める場合はダブルヘッダー第1・第2試合として表現します。試合数は変わりません。baseline生成では雨天率を0に固定し、日程イベントと打席バランスの乱数列を分離しています。

## 選手成長・覚醒・怪我

`growPlayer` は成熟型ごとのピーク年齢を基準に、遠い育成期、成長期、急成長期、ピーク接近期、停滞期、段階的な衰退期を進みます。超早熟は20代前半、通常は20代後半、超晩成は30代前半以降にピークが移るため、晩成型が単に初期能力の低い選手になることを防ぎます。新人生成時の潜在能力には現在年齢からピークまでの未成熟分を加え、遅い成熟型ほど長い成長余地を持たせます。

衰退は潜在能力との差ではなく現在能力を基準に計算するため、能力が潜在上限へ到達したスターもピーク後は段階的に低下します。各パラメータには最大 `±0.25` の左右対称な年間変動を加え、丸めで変化なしの場合はキャリア段階と同方向へ最低1変化させます。能力値の上限は、生成時に存在する記録級選手を成長処理で99へ切り下げないよう120です。

試合終了後は、その試合の打席ログに登場した打者・投手だけを対象に、シーズン中覚醒と怪我を判定します。覚醒は既存の `checkAwakening(player, true)` を利用し、同一シーズン中は1選手1回までです。シーズン中の基礎確率は、143試合の累積判定を考慮して `0.0001` としています。オフシーズンの `growthPhase` による基礎確率 `0.012` は変更していません。

怪我は出場選手1人・1試合あたり `0.00075` で判定します。重症度と復帰までの試合数は次のとおりです。

- light: 74%、2〜5試合
- mid: 23%、8〜18試合
- heavy: 3%、35〜70試合

heavyだけは、投手・野手それぞれの関連パラメータから1〜2項目を選び、各1〜2ポイントを恒久的に低下させます。負傷中の選手は先発、打線、救援候補から除外され、所属球団の試合終了ごとに残り日数が1減ります。

20シーズンの固定seed診断では、リーグ全体の年平均がシーズン中覚醒3.35人、オフシーズン覚醒26.45人、特殊能力獲得0.45人、怪我14.95件でした。怪我の内訳はlight 9.85件、mid 4.70件、heavy 0.40件です。

## 外国人選手の循環

外国人候補には出身国、来日年、1〜3年の契約、NPB在籍年数、日本野球への適応係数を持たせます。適応係数は打席・投球能力と表示OVRへ反映され、来日時点の期待を下回るケース、経験と成績によって適応するケース、まれに大きく上振れるケースがあります。共通の能力上限や年間成績の上限は設けません。

オフシーズンには前年成績と適応状況から契約を見直し、複数年契約中の残留、契約更新、契約満了退団、若い支配的選手のまれなMLB移籍を処理します。CPU球団と操作球団は同じ判定を利用し、契約動向は操作球団の通知に残ります。旧セーブでは従来の外国人加入記録から外国人選手を識別し、初回契約見直し時に互換プロフィールを補います。

ゲーム内の出場選手登録を簡略化し、各球団の外国人登録は5人まで、同時に打線へ入る外国人野手は3人までとします。投手は試合中に同時出場するのが1人なので、外国人投手1人・野手3人の同時出場上限を満たします。

## 投手起用と疲労

先発・中継ぎ・クローザーは登板後の投球数、役割、スタミナ、連投数に応じて疲労が蓄積し、試合間の暦日数に応じて回復します。ブルペンはOVRだけでなく疲労と連投状況も評価して起用するため、同じ最高OVRの中継ぎが毎試合投げ続けることを防ぎます。通常の候補が尽きた場合だけ疲労した投手を緊急登板させるため、登板数そのものを固定する上限はありません。

継投時の目安投球数は先発と救援で分け、救援はおおむね1イニング単位で交代します。高能力域の奪三振・与四球・被本塁打への影響には滑らかな逓減を入れ、平均的な投手との差を残しつつ、極端なK/9や防御率0点台がリーグに大量発生しないようにします。年間200奪三振や防御率1点台を人数で制限する処理はなく、能力・登板機会・確率が重なれば記録級シーズンは引き続き発生します。診断レンジは、2025年NPBの[セ・リーグ投手成績](https://npb.jp/bis/2025/stats/pit_c.html)と[パ・リーグ投手成績](https://npb.jp/bis/2025/stats/pit_p.html)を参考にしています。

## React UI

Phase Cでは、旧 `NPBSimulator` が一括して持っていた画面遷移と状態を次の構成へ分割しています。

- `src/components/screens/`: 球団選択、シーズン、ポストシーズン、オフシーズン、FA・外国人市場、トレード、ドラフト
- `src/components/widgets/`: 選手詳細、ロスター、順位表、ボックススコア、セーブ枠管理
- `src/state/gameState.tsx`: Contextによる全体状態とengine呼び出し
- `src/state/storage.ts`: 保存、読込、複数スロット、JSON入出力、旧セーブのマイグレーション
- `src/state/offseason.ts`: オフシーズン画面固有の進行補助

ゲーム計算は `src/engine` を直接利用し、UI側に打席・試合・成長確率の別実装は持ちません。

## セーブ互換性

新しい保存キーは `npb_sim_v3_slot_1` から `npb_sim_v3_slot_3` までの3枠です。旧キー `npb_sim_v3_restored` が存在し、スロット1が空の場合は、初回読込時に旧データをスロット1へコピーします。旧キーは削除しないため、移行中も元データが失われません。

読込時には以下も補完します。

- `specials` だけを持つ旧選手データから `specialLevels` を生成
- `park` を持たない旧球団データへ現在の球場係数を追加
- 旧日程へ当初日、順延元、ダブルヘッダー情報の既定値を追加
- 不足している成績マップ、通知、年度別成績、引退選手履歴を空値で補完
- `viewTeam` がない旧セーブでは `playerTeam` を利用
- 日程から順位表を再構築可能な既定値を設定

各スロットはJSONファイルとしてダウンロードでき、同じUIから任意のスロットへアップロードできます。アップロード時も通常のマイグレーションを通すため、旧形式のJSONを読み込めます。

## NPB得点環境の目標

2025年NPBの水準を基準に、初期ロスターの100シーズン平均と継続フランチャイズの初年度・25年目について、次の範囲を合格条件とします。

- リーグ打率: `.232`〜`.257`（目安 `.244`）
- リーグ防御率: `2.21`〜`3.60`（目安 `3.01`）
- リーグ年間本塁打: `1,000`〜`1,200`本（参照値 `1,096`本）

目標値は `scripts/npb-targets.mjs` に集約しています。`AT_BAT_BALANCE` では、選手・球団・球場・特殊能力による相対差を維持したまま、リーグ全体の本塁打倍率、インプレー安打率、飛球安打の長打内訳、四球の能力感応度を調整しています。年齢別の成長曲線は変更していません。

## 継続フランチャイズのドリフト診断

独立した初期ロスターを繰り返す通常のbalance baselineとは別に、同じ選手と球団を複数年連続で進め、成長・衰退、引退、ドラフト補充後の長期的なOVRとリーグ成績を確認できます。

```bash
npm run drift
```

既定では2026年から25シーズンをseed `20260724`で実行し、結果を `baseline/franchise-drift.json` へ出力します。年数、開始年、seed、出力先は変更できます。

```bash
npm run drift -- --years 30 --start-year 2026 --seed 20260724 --output baseline/franchise-drift.json
```

診断と実際のゲーム進行は `src/engine/offseason.ts` の同じCPUオフシーズン処理を利用します。成長後に各CPU球団がドラフト6巡分の枠を作り、42歳以上、35歳以上かつOVR 55以下、保持価値の低い選手の順で整理します。その後、FA・外国人市場、ドラフト、最終ロースター競争を進め、各球団の投手28人・野手35人を維持します。操作球団はCPUの整理と自動入札から除外され、従来どおり画面上で引退・補強・指名を決めます。

ドラフト候補は96人で、投手40人・野手56人を必ず生成します。CPUは現在の投手・野手不足を指名ごとに再評価するため、年数経過で特定カテゴリだけが減り続けることを防ぎつつ、高卒・大卒・社会人や怪物候補の確率的な揺らぎは残します。

各年について開幕時とドラフト後の野手・投手平均OVR、球団間OVR格差、平均年齢、年齢帯別人数・OVR、成熟型構成、エリート潜在能力・OVR85以上の人数、外国人数・平均在籍年数・適応分布、引退・指名人数に加え、リーグ打率、BABIP、防御率、本塁打、得点、四球率、三振率を記録します。外国人の新規加入、契約更新、契約満了退団、MLB移籍も年ごとに残します。個人成績は30本塁打・100打点・防御率1点未満／2点未満・180／200奪三振・救援60／70登板・救援90投球回の人数と各部門トップも残すため、平均値だけでなく分布の裾と異常な起用を追跡できます。各年の目標判定も記録し、コマンドは初年度または最終年度がNPB目標レンジ外なら失敗します。

現在の25年診断値は `baseline/franchise-drift.json` に保存します。

## バランス基準値

現在のTypeScriptエンジンを100シーズン・seed `20260723`で実行し、承認済みの基準値を `baseline/season-stats.json` へ記録します。バランスを意図的に変更した回では、このコマンドで新しい数値を基準として採用します。

```bash
npm run baseline
```

比較用の現在値は `baseline/new-season-stats.json` へ生成します。

```bash
npm run baseline:new
```

`npm run baseline:compare` は、打率、防御率、本塁打、盗塁成功率、四球率の平均と母標準偏差について、記録済み基準から2%を超える予期しない変動を検出します。さらに、打率・防御率・本塁打の平均がNPB目標レンジ内であることも確認します。

```bash
npm run baseline:compare
```

現在の100シーズン平均は、打率 `.246028`、防御率 `2.986785`、リーグ年間本塁打 `1,124.27`本です。
